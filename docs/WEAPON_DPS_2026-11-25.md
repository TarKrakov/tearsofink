## Методика и границы

- Источники: ModItems, ModTiers (Асфода +2), InkGreatswordItem, OrdinaryWeaponItem, SoulShieldItem, InkLongknifeItem, Archetype, Gear, Combat, Combos, weapon_combos/*.json. Атрибут урона — 1 (кулак) + материал + прибавка, скорости — 4 + модификатор. Обычное оружие передаёт итоговые атрибуты. Для Gear множители ступеней 1/1,15/1,30 при прочих равных; износ не моделируется.
- Для каждого шага duration/hit = max(1, Java Math.round(source / tempo)). Темп зависит от хвата. Шкала сбрасывается при старте; её естественный прирост и Combat.fastFill с дробным carry моделируются по тикам, до min_strength с +0,5 тика. Интервал старта следующего шага = max(duration, тики зарядки). Включается восстановление после последнего шага. Полная связка использует полные коэффициенты damage, не штраф недозаряда. В текущих JSON нет second_hit.
- Чистый DPS = сумма всех номинальных попаданий ×20 / суммарные тики цикла. Модель i-frames: обычное 10-тиковое защитное окно, в нём проходит только положительная разность от максимального принятого удара, без перезапуска окна. 1000 повторов после 20 разогревающих циклов. Для обычного ванильного ЛКМ — полностью заряженные удары без критов. Идеальный ввод, без сетевой задержки; порядок клиентских/серверных событий может сместить попадания на тик. Значения около границы i-frames чувствительны к такому смещению. Не моделируется оптимизация через намеренное ожидание между ударами, прерывание серии, особые правила урона мобов или реальные промахи.
