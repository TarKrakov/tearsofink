# Бледный двуручник — переключаемый блок и постановка по рисункам

17 ноября 2026, поверх `a637abf`. Уточнение автора заменяет короткий блок D-029 переключаемой стойкой. Новый Shift+R поднимает мечи, повторный Shift+R опускает. Отпускать Shift/R для удержания стойки не требуется; автоматического окончания через 1–1.2 секунды больше нет.

Отключение доступно и во время перезарядки входа. Сама перезарядка по-прежнему начинается при включении: 110 тиков для одного меча / 160 для пары, с прежним множителем пробуждений. Защита заканчивается сразу при выключении, а оружие плавно опускается; этот переход можно продолжить другим действием. Смена предметов, смерть, выход, недопустимое состояние или измерение отменяют блок. Пока стойка включена, боевые действия остаются заблокированы прежним `locked`; ходьба не отключается. Опускание не сбрасывает скорость игрока.

## Поза

- Один меч справа: рукоять справа внизу, остриё слева вверху; клинок идёт перед персонажем по диагонали примерно через половину экрана. Режущая кромка направлена от игрока к врагу, поэтому со стороны камеры меч виден узкой стороной. Для меча в левой руке сохранена отдельная зеркальная постановка через собственный авторский Display.
- Пара: широкий X перед игроком; рукояти в нижних противоположных углах, острия — в верхних. Плоскости клинков обращены к игроку/врагу, кромки смотрят в стороны вниз по жёлтым стрелкам. Между клинками небольшой зазор по глубине, чтобы они не занимали одну плоскость в месте пересечения. Это отдельные клипы, не копия `dual_parry`.
- В F5 плечи ведут хват, кисть сохраняет нужную ориентацию клинка. Авторские модель, текстура, масштаб, Display и Blockbench не менялись. ЛКМ, ПКМ и обычный R не переставлялись; полученные из main новые боевые числа сохранены.

## Реализация и настройки

Серверная фаза `GUARD` теперь действует до выключения/отмены. Через каждые 30 тиков сервер обновляет только **удерживаемый** клип `guard_hold` / `dual_guard_hold`: его начальная поза уже поднята, поэтому повторного замаха/провала нет. Это поддерживает длительное отображение и у наблюдателей без новых общих режимов рендера. Промежуток обновления — техническая синхронизация, а не срок защиты. Опускание — отдельный `guard_release`, смешиваемый из реально показанной позы.

Снижение входящего урона и сектор остались прежними: один меч 45% / 120°, два 60% / 150°. Это частичная фронтальная защита, без контрудара и отражения. Все текущие коэффициенты/перезарядки остаются в `data/tears-of-ink/weapon_moves/pale_linear_greatsword.json`. Устаревшие `single_duration_ticks` / `dual_duration_ticks` удалены из настроек и больше не ограничивают стойку; старые datapack могут содержать эти неиспользуемые поля. Остальной баланс не менялся.

Позы воспроизводятся `python3 tools/preview/pale_guard_poses.py`. Генератор пишет только клипы блока и их источники, сохраняет остальные анимации. Для предпросмотра: `python3 tools/preview/pale.py out/guard solo-guard dual-guard`.

## Проверки

Сборка JDK25 / release21 прошла. `check_pale_guard.py` проверяет все четыре позы: полную геометрию в кадре, направление кромки одиночного блока, нормаль плоскости парного, отличие от парирования, совпадение FP/F5 на обновлении. Реальная последовательность при 120 Гц остаётся неподвижной через два обновления, затем возвращается в спокойную стойку. Просмотрены крупные FP-кадры и F5.

На локальном dedicated-сервере с сетевым клиентом, normal difficulty: удар в 4 HP спереди оставляет 2.2 HP урона при одном мече и 1.6 при паре. Те же значения сохраняются после более четырёх секунд и нескольких обновлений. Сзади проходит полный урон. Повторный Shift+R, включая быстрое нажатие внутри cooldown, прекращает защиту; после смены оружия защита также исчезает. Графический Minecraft-клиент не запускался, новая художественная оценка ожидается.

Общие проверки FP, pivot, стыков, полёта и парной синхронности прошли. Дополнительно исправлены две проверки, устаревшие после уже полученных изменений main: скорость атаки теперь проверяется как редактируемый баланс, а не равенство донору; F5-хеши нормализуют JSON-числа `0`/`0.0`. Новые нормализованные снимки рассчитаны из исходного `ee55b6e`, прежние хеши сохранены; реальные изменения геометрии по-прежнему обнаруживаются. Это исправления проверок, не правка боевых чисел.

Общие тесты также приведены в соответствие с уже полученным main: скорость заполнения шкалы ЛКМ после балансировки проверяется как настраиваемое положительное число, а не как старое число топора. F5-снимки по-прежнему сверяются с `ee55b6e`, но числа JSON нормализованы перед хешированием: `0` и `0.0` — одна поза. Исходные исторические хеши сохранены рядом с нормализованными. Игровой баланс этой правкой тестов не менялся.
