# ТЗ Codex — сменная арена настоящего Пантеона (24 ноября 2026)

Цель: подключить безопасную смену окружений к уже существующему авторскому храму в pantheon_temple. Не создавать новый мир и не переносить пилот целиком. Кодекс привлекается только к этой сложной системной задаче; рутинный арт, алтарь, реликвии, боссы и баланс не входят в этап.

1. Сверить AGENTS.md, PROJECT_STATUS.md, DECISIONS.md, PANTHEON_ARENA_IMPLEMENTATION_PLAN_2026-11-23.md, PANTHEON_SCHEMATIC_REVIEW_2026-11-24.md; фактические PantheonTemple, PantheonPrototype, PantheonTravel, защитные миксины и оригинальный schematic. Измерение уже имеет ключ/защиту/нейтральный закат.
2. По реальной геометрии определить и зафиксировать точную ограниченную маску сменного интерьера (не весь прямоугольник после Z=39). Постоянный каркас, коридор, колонны, светильники, купель, станции, сундук и будущие точки наблюдения неприкосновенны. Ориентиры 57×47/92×84 — не константы. Не менять исходный schematic и не создавать художественные ассеты.
3. Серверный менеджер сцены: NEUTRAL, PREPARING, READY, RESTORING (или эквивалент). Сохранение состояния, одновременная операция не допускается, временно закрытый проход, безопасная эвакуация из изменяемой зоны. Операции по тикам, ограничение чанков, обработка жидкости, блок-сущностей, света и восстановления при рестарте. Запрет изменения архитектуры для всех обычных игроков остаётся. Разрешить только проверенные внутренние записи менеджера, без глобального снятия защиты.
4. Сделать две операторские технические сцены (лес и остров) только из существующих блоков, плюс точное восстановление исходного нейтрального пола и свободного поля. Никакой автоматической перестройки при входе. Команды смены/сброса/статуса, диагностика объёма, длительности и пиковой стоимости порции. Закат нейтрального профиля сохранить; предусмотреть точку расширения для окружения будущих боссов без обязательной реализации дополнительных эффектов.
5. Проверить на выделенном сервере и старой установленной копии: лес → остров → нейтральная → повтор; отсутствие утечки воды, повреждения/перезаписи хаба, дублирования block entities, конфликтов защиты; отключение/рестарт в середине и повторный вход, два игрока, работа ключа и станций. Сравнить хеш или снимок постоянного объёма до/после. Проверить сборку и CI. Если полноценный клиент не доступен — явно указать, что визуальная приёмка отдельно.
6. Работать прямо в main, небольшими проверяемыми коммитами, обновить PROJECT_STATUS и тематическую документацию. Не менять оружие, Жатву, сюжет, руины, баланс, реликвии, награды, боевую сессию и авторский арт. Не создавать PR/ветку без необходимости.

Критерий окончания: большая реальная арена меняется и восстанавливается по команде, не портит храм и не теряет состояние при рестарте. Следующие задачи — алтарь/реликвии и отдельная система боевых сессий, затем первый полноценный босс.
