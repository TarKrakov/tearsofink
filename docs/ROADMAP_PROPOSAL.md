# Tears of Ink — предложенная дорожная карта разработки

**Статус:** рабочее **предложение ChatGPT**, **не утверждённое решение автора**. Составлено 16 ноября 2026 по авторскому `Tears_of_Ink.md`, коду GitHub, `PROJECT_STATUS.md` и новым утверждённым правилам экипировки. Разделять этот план и игровые требования автора: никакие даты, конкретные характеристики или очередность PR не утверждены, пока автор не подтвердит. Сохранять выполненные системы без переработки.

## Цель ближайшего цикла

**Цельность игрового прохождения**: вход в Чернильные Земли → региональные ресурсы → выбор обычного оружия и брони → приёмы, заточка, пробуждения → контракты и охотничья экипировка → сооружённая игроком Купель → первая Рубрика, ориентир **3–5 часов от первого прибытия**. Остальные механики, включая фракции/Жатву/торговлю, уже участвуют в петле, поэтому править их только при подтверждённом конкретном узком месте.

## Разделение работ внутри каждого этапа

- **Геймдизайн (автор):** смысл и специфика оружия, вид и движения, приоритет арт-ресурсов, окончательные числа баланса.
- **Анализ (ChatGPT):** код + история решений → точная экономика, проектные таблицы, технические задания Codex, ревью PR, корректировка документации.
- **Реализация (Codex):** отдельная ветка и маленькие PR; перед кодом смотреть текущие классы; отчёт: файлы, проверки, ошибки, остающиеся работы; не мержить.
- **Арт (автор):** Blockbench/Aseprite, 3D-модели, текстуры, украшения, эффекты/звуки. **Не создавать и не заменять временные ресурсы без отдельного разрешения.**
- **Анимационный конвейер:** словесная постановка автора → расчёт keyframes/JSON → Python GIF с трёх ракурсов → обратная связь автора → Minecraft. `tools/preview` не генератор естественного языка сам по себе — описание интерпретирует ассистент/Codex.

## Этапы дробить на отдельные PR, а не один гигантский

Первые три самостоятельные технические задачи после принятия документации (предложение):
1. **animation-preview-smoke:** воспроизводимый запуск существующих семи архетипов и портативные пути, без изменений игровых движений.
2. **equipment-foundation:** техническая основа типов/рецептур/параметров; только то, что нужно первому бледному срезу; сохранить существующие `PALE_SWORD` и `DIM_SCIMITAR` в сохранениях, согласовать миграцию до изменения ID.
3. **pale-equipment-slice:** 3 вида бледного оружия, 12 частей брони и физические приёмы. Возможные отдельные PR: регистрация/предметы, боевые приёмы, броня/рендер, рецепты/лут, визуальные ресурсы.

Этап «обычное оружие» не требует создавать полностью новую боевую архитектуру: есть `Skill` с нулевой ценой и cooldown, `Skills.activate`, `Combos`, `Archetype`, `Gear`, `Awakening`. Проверять интерфейс и взаимодействие, не переписывать рабочие классы без нужды. Сейчас `OrdinaryWeaponItem.ability()==null`, обычных мечей 6 (по 2 линии), на каждый из них один слот пробуждения. **Не объявлять новые 9 мечей реализованными до PR.**

## Контрольные тесты

- Документация: ссылки, diff, соответствие кодовому состоянию; ни один аналитический вывод не присвоен автору как утверждённое решение.
- Код: сборка Gradle, проверки соответствующей системы и отрицательных сценариев; только фактически запущенные проверки считать прошедшими.
- Оружие: GUI, R/Shift+R и цена 0 ресурсов, кд, износ и пробуждения, одиночный/двойной хват, клиент/сервер, F5 и рука; анимации на модели автора. Проверка игровых сохранений до/после и отображения старого оружия.
- Броня: 4 слота, характеристики/мобильность, тройка весов, износ/ступени, пробуждения, совместимость со скинами Steve/Alex и кооперативом; тест без моделей нельзя объявлять визуально завершённым.
- Экономика: источник каждого сырья реально доступен до крафта, нет непреднамеренной блокировки, стоп-время от первого попадания до Рубрики, запас ресурсов/срок строительства Купели; отдельно тестировать контракты и Жатву.
- Любые правки worldgen — отдельная область риска и отдельные серверные тесты; не менять в PR экипировки без нужды.
