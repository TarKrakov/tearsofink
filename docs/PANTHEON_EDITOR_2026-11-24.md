# Редактор нейтральной арены Пантеона (24 ноября 2026)
Первый рабочий этап по запросу автора. Оператор в creative, один в установленном Пантеоне, без активного испытания. Команды:

- /tearsofink pantheon edit start — сохраняет резервную копию блоков, разрешает строительство внутри области и блокирует ритуалы.
- /tearsofink pantheon edit save — проверяет новый baseline и маску сцен, сохраняет в конкретном мире, возвращает защиту.
- /tearsofink pantheon edit cancel — порционный откат к копии до начала редактирования.
- /tearsofink pantheon edit status — состояние.
- /tearsofink pantheon edit export — экспорт сохранённой редакции в папку pantheon_exports внутри сохранения, .schem Sponge v2; исходная схема храма и её NBT вне области остаются прежними. Это не автоматическая замена ресурса мода и не миграция других миров.

Область world X -40..42, Y 81..101, Z 45..127 (локально X17..99, Y1..21, Z45..127). Вне неё защита действует. Фундамент, проход, хаб, внешние стены, станции, метки установки не редактируются. Существующие блок-сущности нельзя менять, новые добавлять нельзя; жидкости не размещаются. Для тестовых сцен сохраняется свободный центральный проход local X57..59, Z45..86: цельный пол на Y1, воздух до Y21. При сохранении проверяется герметичность острова. Декоративные занятые столбцы исключаются из маски сцены, свободные с полным твёрдым полом могут использоваться сценами; сброс восстанавливает новое состояние. Никаких новых ассетов.

Резерв и baseline хранятся атомарно в data/tearsofink_pantheon_edit_v1.dat. Если сервер выключился во время редактирования, при следующем запуске режим остаётся открытым только для владельца; старый журнал сцен не применяется. Можно продолжить или отменить. Если прервался откат, повторить cancel. При ошибке чтения журнала ритуалы блокируются; сохранить резервную копию файла перед ручным восстановлением. Сохранение и экспорт требуют краткого синхронного чтения чанков; откат ограничен 512 записями за тик. Не менять размер храма и координаты боевой логики.

Ограничение: vanilla/командные инструменты, которые используют Level.setBlock, поддерживаются по коду; Axiom требует реальной проверки, в частности bulk-операции, которые могут обходить общий хук. Не использовать Axiom за пределами выделенной области или для сущностей/блок-сущностей до отдельной проверки. Экспорт содержит исходные маркеры и NBT схемы, а не живые инвентари. Для включения в мод требуется отдельная проверка импорта, защиты и миграции; исходный импорт очищает dirt/grass/path как старый случайный грунт, что нужно учитывать при включении новой схемы.

Приёмка ожидается: build/CI, start/обычная установка и разрушение, запрет за пределами, save→лес→reset, cancel→повторный запуск, рестарт с открытой редакцией и после сохранения, экспорт в Axiom, отказ ритуала/смены сцен, второй игрок, центральный проход и отсутствие повреждения станций.
