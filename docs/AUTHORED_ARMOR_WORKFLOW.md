# Авторская объёмная броня — первый комплект (20 ноября 2026)

Автор передал `blockbench/pale_heavy_armor.bbmodel` и `textures/armor/pale_heavy_armor_texture.png`, и попросил сначала подключить надеваемый 3D-комплект, иконки позже. Оригиналы и существующие предметы/крафт/баланс сохранены.

## Конвейер
- Один Generic Model (.bbmodel 5.0), один PNG. Нейтральные кости: root — head, body, right_arm, left_arm, right_leg, left_leg (допускается вложенность arms в body). Их pivot не менять; узлы брони ниже соответствующей кости: helmet, chestplate, chestplate_right_arm, chestplate_left_arm, leggings_waist, leggings_right, leggings_left, boot_right, boot_left. Имена кубов произвольны. Манекен вне названных групп игнорируется.
- Gradle processResources включает `blockbench/*_armor.bbmodel` в assets/tears-of-ink/armor_models. Клиент один раз разбирает BB 5.0 groups/outliner, запекает грани, привязывает локальные координаты к фактическим ModelPart игрока. Новый комплект — те же группы, свой файл/текстура и одна регистрация четырёх существующих предметов. Не нужен GeckoLib.
- UV нормируются по uv_width/uv_height (фактически 64×64 при PNG 128×128); сохраняются per-face UV, их развороты, Inflate, вращения кубов/вложенных групп. Нулевые исходные размеры с Inflate остаются объёмными; имеющиеся схлопнутые UV не перерисовываются. Пока только кубы, одна текстура, нейтральные основные кости; stretch, mesh, анимации самой брони не поддерживаются.
- Fabric ArmorRenderer заменяет ванильный слой только четырёх pale heavy вещей; получает текущую позу тела, включая ThirdPerson, щиты, ходьбу, присед, плавание. Отдельная часть рисует только свой слот. На Steve (широкие руки) геометрия авторской брони сохраняется в точности. На Alex (тонкие руки) наручи автоматически сужаются по X с 4 до 3 пикселей, сохраняя внутренний край руки; используем реальный pivot и поворот кости. Это визуальное преобразование только при надевании (F5 и видимые FP руки), не меняет BB/PNG/UV или 3D-превью предмета. Видимые ванильные руки FP (пустая рука/карта) покрываются наручами; текущий FP клинков рисует предмет без рук, новые руки не добавляются. Инвентарный внешний вид временно прежний. 

## Проверка
Статически по авторскому исходнику: 20 кубов, 120 граней, 28 схлопнутых UV (исходный арт), 8 непустых подгрупп, все UV в пределах логических 64×64; физический PNG 128×128. CI запускается по push; сборка и реальная игра проверяются отдельно.

Игровая приёмка: надеть каждую часть отдельно, затем комплект; F5 спереди/сзади, поворот головы, ходьба, бег, присед, прыжок, плавание, бой с одиночным/парным оружием, пустая рука FP; Steve/Alex, второму игроку видна та же броня, смешение с ванильными частями. Если что-то просвечивает — сначала сопоставить с авторским BB, не править PNG/геометрию без разрешения.

**Авторская приёмка:** автор сообщил, что первый комплект в игре работает нормально. Детализированная матрица поз и Alex не подтверждены отдельно. D-096 меняет только отображаемые имена, поэтому имена PNG/BB и внутренние ID для конвейера остаются прежними.

## Второй комплект и временные 3D-иконки (20 ноября 2026)
Средний бледный комплект: pale_medium_armor.bbmodel + plate_medium_armor_texture.png (имя из BB, не переименовывать), 14 кубов, 84 грани, UV 128×128, PNG 256×256. Для двух готовых комплектов (8 предметов) добавлено 3D-представление из существующей геометрии каждого слота; нейтральная поза, восстановление авторских pivot, центрирование по границам, вписывание в сферу диаметром 0,90, общий display JSON. BuiltinItemRendererRegistry по примеру помпы, GUI/земля/рамка/обе руки, исходная текстура и glint. Будущие плоские иконки подключаются заменой parent на item/generated у нужного предмета, надевание независимо. Прочие 28 предметов остаются с заглушками, пока нет авторских моделей. Исходные BB/PNG, идентификаторы, рецепты и баланс не изменены.

Проверка: обе модели и PNG сверены по регистрации, размерам, принадлежности всех кубов к слотам; расчёт габаритов всех восьми предметов в нейтральной позе, нормализация в сферу. Средняя модель без схлопнутых UV; тяжёлая сохраняет 28 исходных схлопнутых UV. В GUI проверить читаемость всех частей, особенно поножей/ботинок, вид в руке, на земле, в рамке, чары, и надевание в смешанном комплекте. Сборка CI при push; игра после этой правки не проверена.

## Третий комплект — лёгкая бледная броня (21 ноября 2026)

По запросу автора подключён `blockbench/pale_light_armor.bbmodel` к уже существующему клиентскому конвейеру `AuthoredArmorRenderer`, как тяжёлый и средний варианты. Автор завершил геометрию; `textures/armor/pale_light_armor.png` — **временная авторская текстура**. Её можно дорисовать и заменить **по тому же пути**, без изменения ID предметов, рендера или BB. Исходная геометрия, UV и PNG не изменялись.

Четыре существующих предмета: `pale_headband` (голова), `pale_quilted_jacket` (корпус и руки), `pale_pants` (поножи), `pale_shoes` (ботинки). Все четыре используют `tears-of-ink:item/authored_armor_preview` и тот же встроенный 3D-рендер при надевании и в GUI/руке/на земле. Значения защиты, скорость, рецепты и логика пробуждения не менялись.

Проверка исходного BB: 28 кубов всего, из них 24 принадлежат слотам (7 шлем, 11 куртка, 2 поножи, 4 ботинки), ещё 4 — манекену вне слотов и игнорируются. 144 включённых граней, 0 схлопнутых UV; UV в пределах логических 128×128; одна текстура `pale_light_armor.png` (PNG 128×128). Основные узлы/кости нейтральны, ожидаемые имена подгрупп совпадают с конвейером. Для практической проверки: части отдельно, полный комплект, F5, руки FP, Steve/Alex, мультиплеер, 3D в инвентаре. Статическая проверка не означает проверку в Minecraft.

## Steve / Alex: подгонка рук (21 ноября 2026)

После замечания автора исправлено соответствие всех трёх бледных комплектов модели игрока. Выбор **classic / slim** определяется реальной моделью скина `AbstractClientPlayer.getSkin().model()` на клиенте, а не полом персонажа, именем игрока или инвентарным предметом. Кости головы, корпуса, ног и слотные 3D-иконки не меняются; для рук Alex матрица после позы текущей кости уменьшает ширину по локальной X с 4 до 3 модельных пикселей. Смещение от центра сохраняет внутренний (ближайший к телу) край и уменьшает только внешнюю сторону рукава; узор и UV остаются исходными. Для Steve преобразование не применяется. Тот же код применяется к собственному персонажу в F5, удалённым игрокам и видимым рукам от первого лица (пустая рука/карта).

Введён отдельный чистый `ArmorArmFit` и тест `tools/tests/ArmorArmFitTest.java` (проверка обоих внутренних и внешних краёв, зеркальности и масштаба); CI запускает его до Gradle. Исходные `.bbmodel` и PNG не тронуты. В Minecraft остаётся проверить оба типа модели с разной бронёй и во всех позах, особенно границу плеча/рукава, а также разные скины двух игроков. Для предметов в GUI изменение намеренно не применяется — у них нет владельца скина.
