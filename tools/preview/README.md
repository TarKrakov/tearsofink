# Превью ударов (для Claude)

Рисует от первого лица и Стива в третьем лице (сзади и спереди) по файлам `weapon_anims/*.json` — той же математикой, что `client/combat/ThirdPerson.java` и `WeaponAnims.java`. **Менять их вместе:** если меняется расчёт в Java — повторить здесь.

Нужны `numpy`, `pillow` (шрифт DejaVu для подписей).

- `third.py` — математика: сэмплинг движений (spline, hold), рукоять/кончик (`axis`), третье лицо `solve4` (с поправками `third`: wrist_hold, mirror, center, lateral, no_cross), простой рендер.
- `run.py` — `cell()` одна поза; `python3 run.py <архетип> [движения]` — лист поз.
- `tl.py` — `build(arch, steps, dual, out.gif)` — гифка серии (шаги из `weapon_combos`); `python3 tl.py executioner scimitar …` — все архетипы.
- `pair.py` — `pair(arch, main, off, times, fix=…)` — обе руки, поправки на пробу.
- `edge.py` — `edge_align(clip, keys)` — довернуть клинок вокруг оси, чтобы кромка (выпуклая сторона) шла по ходу движения.
- `hilt.py` — расчёт позы «клинок назад вдоль руки» (удар эфесом).
- `twtest.py` — `run(clipname, clip, times, out, single=…)` — проверить движение до записи в JSON.

## Пилот Бледного линейного двуручника (17 ноября 2026)

- `python3 tools/preview/check_pale.py` — проверка шести шагов (3 одиночных и 3 парных), моментов попаданий, направления уколов и неподвижности pivot (2 480 выборок).
- `python3 tools/preview/pale.py out/pale` — три одиночных и три парных удара, обе серии, R из каждого одиночного удара, парные ПКМ/R и умение слева. Каждый кадр включает все три ракурса.
- `tl.py` учитывает настройки `third` архетипа и смешивает фактически показанные позы рук и кистей, как игровой клиент. `all_for` учитывает `tempo` в длительности шагов.
- Готовые основные GIF: [docs/previews/pale-linear-greatsword](../../docs/previews/pale-linear-greatsword/README.md).

Просмотрщик окрашивает геометрию для различения рук; он не является захватом материалов/текстуры из Minecraft и не моделирует физику сущности или серверные попадания.

## Быстрый контроль новых мечей — одна команда

После добавления `weapon_anims/<архетип>.json` и `weapon_combos/<архетип>.json`:

```bash
python3 tools/preview/review.py pale_linear_greatsword --check-only
python3 tools/preview/review.py pale_linear_greatsword --render
```

Второй вызов создаёт `out/review/<архетип>/`:
- `report.json` — видимость **всех вершин модели** на ключевых кадрах и в момент попадания, размер перемещения кончика между выборками, привязка к предплечью в F5, предупреждения;
- `solo.gif`, `dual.gif`, `charge.gif` (если есть парная зарядка);
- `solo.png`, `dual.png`, `charge.png` — контактные листы из 12 кадров, **каждый в трёх ракурсах**: F5 сзади, F5 спереди и первое лицо.

Новый архетип не нужно дописывать в `ITEM` файла `run.py`, если `models/item/<архетип>.json` существует и содержит 3D-геометрию либо наследует её через `parent`. Просмотрщик разрешает наследование исходной Blockbench-модели и сохраняет дочерние Display-позы. Для корректного просмотра нужны author-defined `firstperson_*` и `thirdperson_*` позы обеих рук. Плоскую иконку вместо 3D-модели не подставлять.

В CI на каждом push выполняются `check_pale.py` и `review.py ... --check-only`; коммит с `[preview]` дополнительно публикует в GitHub Actions артефакт **WeaponAnimationReview** с GIF/PNG/отчётом. Специальный парный R публикуется отдельно в **PaleGreatswordSpecialtyPreview**.

**Предел достоверности:** это математические проверки и предварительная визуализация. Отчёт не заменяет художественный просмотр анимации целиком в GIF и тест Minecraft. Порог «видимость на ударе» — предупреждение, а не запрет: для разных анимаций допустимые зоны и выход рукояти за край отличаются. Высокая скорость кончика сама по себе не ошибка, если удар должен быть резким.
