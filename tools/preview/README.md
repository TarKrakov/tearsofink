# Превью ударов (для Claude)

Рисует от первого лица и Стива в третьем лице (сзади и спереди) по файлам `weapon_anims/*.json` — той же математикой, что `client/combat/ThirdPerson.java` и `WeaponAnims.java`. **Менять их вместе:** если меняется расчёт в Java — повторить здесь.

Нужны `numpy`, `pillow` (шрифт DejaVu для подписей).

- `third.py` — математика: сэмплинг движений (spline, hold), рукоять/кончик (`axis`), третье лицо `solve4` (с поправками `third`: wrist_hold, mirror, center, lateral, no_cross), простой рендер.
- `run.py` — `cell()` одна поза; `python3 run.py <архетип> [движения]` — лист поз.
- `tl.py` — `build(arch, steps, dual, out.gif)` — гифка серии (шаги из `weapon_combos`); `python3 tl.py executioner scimitar …` — все архетипы.
- `pair.py` — `pair(arch, main, off, times, fix=…)` — обе руки, поправки на пробу.
- `edge.py` — `edge_align(clip, keys)` — довернуть клинок вокруг оси, чтобы кромка (выпуклая сторона) шла по ходу движения.
- `hilt.py` — расчёт позы «клинок назад вдоль руки» (удар эфесом).
- `twtest.py` — `run(clipname, clip, times, out, single=…)` — проверить движение до записи в JSON.

## Пилот Бледного линейного двуручника (17 ноября 2026)

- `python3 tools/preview/check_pale.py` — проверка шести шагов (3 одиночных и 3 парных), моментов попаданий, направления уколов и неподвижности pivot по всем клипам.
- `python3 tools/preview/pale.py out/pale` — три одиночных и три парных удара, обе серии, R из каждого одиночного удара, парные ПКМ/R и умение слева. Каждый кадр включает все три ракурса.
- `tl.py` учитывает настройки `third` архетипа и смешивает фактически показанные позы рук и кистей, как игровой клиент. `all_for` учитывает `tempo` в длительности шагов.
- Готовые основные GIF: [docs/previews/pale-linear-greatsword](../../docs/previews/pale-linear-greatsword/README.md).

Просмотрщик окрашивает геометрию для различения рук; он не является захватом материалов/текстуры из Minecraft и не моделирует физику сущности или серверные попадания.

## Быстрый контроль новых мечей — одна команда

После добавления `weapon_anims/<архетип>.json` и `weapon_combos/<архетип>.json`:

```bash
python3 tools/preview/review.py pale_linear_greatsword --check-only
python3 tools/preview/review.py pale_linear_greatsword --render
```

Второй вызов создаёт `out/review/<архетип>/`:
- `report.json` — видимость **всех вершин модели** на ключевых кадрах и в момент попадания, размер перемещения кончика между выборками, скачки скорости на границах ключевых кадров, привязка к предплечью в F5, предупреждения;
- `solo.gif`, `dual.gif`, `charge.gif` (если есть парная зарядка);
- `solo.png`, `dual.png`, `charge.png` — контактные листы из 12 кадров, **каждый в трёх ракурсах**: F5 сзади, F5 спереди и первое лицо.

Новый архетип не нужно дописывать в `ITEM` файла `run.py`, если `models/item/<архетип>.json` существует и содержит 3D-геометрию либо наследует её через `parent`. Просмотрщик разрешает наследование исходной Blockbench-модели и сохраняет дочерние Display-позы. Для корректного просмотра нужны author-defined `firstperson_*` и `thirdperson_*` позы обеих рук. Плоскую иконку вместо 3D-модели не подставлять.

В CI на каждом push выполняются `check_pale.py` и `review.py ... --check-only`; коммит с `[preview]` дополнительно публикует в GitHub Actions артефакт **WeaponAnimationReview** с GIF/PNG/отчётом. Специальный парный R публикуется отдельно в **PaleGreatswordSpecialtyPreview**.

**Предел достоверности:** это математические проверки и предварительная визуализация. Отчёт не заменяет художественный просмотр анимации целиком в GIF и тест Minecraft. Порог «видимость на ударе» — предупреждение, а не запрет: для разных анимаций допустимые зоны и выход рукояти за край отличаются. Высокая скорость кончика сама по себе не ошибка, если удар должен быть резким.

## Новая авторская база D-026

- `blade_pose.py`: относительные FP-ключи из положения хвата, направления клинка и ведущей кромки; Display берётся отдельно для каждой руки.
- `rebuild_pale.py`: воспроизводит новую постановку из D-026, пишет только JSON анимаций. Старые ключи не используются как опоры. Не запускать для других/изменённых авторских моделей без повторной проверки baseline.
- `third.arm_space`: `third.source.rotation` задаёт плечевые углы в градусах относительно руки (−18°,0,0); Y/Z учитывают сторону. `third.wrist_source.rotation.x` — подготовленный roll режущей плоскости вокруг настоящей оси клинка в рукояти. Предмет следует за плечом, сохраняя собственный TP Display. Python и Java используют одинаковую цепочку Rz·Ry·Rx, grip и вес входа/выхода. Параметры предназначены для отдельной постановки F5, без `follow_blade`/`mirror`/`push`.
- `rotation_mode: slerp`: короткая интерполяция ориентаций и FP-прерываний; legacy Euler сохраняется по умолчанию. Положение остаётся на tight-кривой.
- `python3 tools/preview/check_pale_space.py`: полные TP-модели при 60 Гц, голова/торс и раздельные парные коридоры.
- `python3 tools/preview/check_pale_edge.py`: плоскость рассечения и согласованное движение рукояти/острия около impact в FP и F5.
- `pale.py` добавляет нейтраль и плотные листы ударов, использует строгий фронтальный F5; остальные архетипы сохраняют прежнюю камеру. Штатное отражение LEFT_HAND в `dR/dT` обязательно и не удаляется.

## Актуальная команда автора D-027: ЛКМ топоров

`python3 tools/preview/pale_axe_transfer.py` переносит 3 одиночных / 5 парных шагов axe и воспроизводит отдельные ПКМ/R меча. `axe_*_raw` — исходные движения; активные ЛКМ имеют ту же кривую с постоянной FP-посадкой Z −16 пикселей, сохраняя raw-источники F5. Модели не редактируются. `check_pale.py` проверяет именно это отличие от исходника и буквальную сохранность остальных каналов; `check_pale_space.py` проверяет парные способности, где защита намеренно пересекает центр. `check_pale_edge.py` проверяет ответ/приземление как продолжение предыдущей стойки (`continuing=True`), а не как новую атаку из покоя. Старый `rebuild_pale.py` исторический и больше не должен перезаписывать эту постановку. Предпросмотр умеет left-only шаг, пять парных шагов и отдельную удерживаемую защиту `parry-cross`.

### Дополнение D-027: компактность и два согласованных клинка

`pale_axe_transfer.py` теперь применяет согласованное уменьшение амплитуды, посадку FP −9 Z, отдельные off-клипы через левый Display и осевой доворот клинков общего удара 3/4. Ритм донора сохранён. `references/pale_solo_r_8b7dd6d.json` — точный источник восстановления одиночного R; `references/pale_pair_slam_before_edge.json` — неизменная техническая поза перед осевым доворотом для проверки рук/траектории.

`python3 tools/preview/check_pale_sync.py` проверяет полную последовательность с реальным смешиванием поз при 120 Гц, зеркальность клинков 3/4, режущую плоскость на попадании и отсутствие переноса руки/оси после доворота. `tl.build` поддерживает необязательные `observer` и `render_frames=False` для такой проверки без повторного рисования; готовая библиотека анимаций переиспользуется между кадрами. `pale.py` выводит дополнительный фрагмент `pair-3-4.gif/png`.

### Исправление внешнего FP-рендера

`python3 tools/preview/check_pale_fp.py --compiled` запускается **после Gradle build**: проверяет экранные FP-позиции 16:9, намеренно разные vanilla equip-параметры, скомпилированный нейтральный вызов 0/0 и early-out, все 29 неизменных F5-снимков, поднятые удары/прямой укол/острия внутрь и ровно однократный подъём зарядки. Нужен JDK с `javap`. `fp_item_m(..., equipped=...)` теперь может воспроизвести старый дополнительный hand-Y; по умолчанию 0 соответствует исправленному рендеру.

`pale.py` сохраняет отдельные `solo-fp`, `pair-fp`, `pair-charge-fp` GIF **960×540** и контактные листы; `pair-3-4-fp.gif` — фрагмент общих атак. `pale_fp_compare.py out/pale` строит техническое сравнение старого equip-зависимого рендера и новой композиции. Оно не является скриншотом запущенного Minecraft. `review.py` использует 16:9 для этого меча, остальные архетипы сохраняют прежние настройки. Исходные F5-позы заморожены в хешах `references/pale_f5_28a2a80.json`, старые FP-позы зарядки — в `references/pale_charge_before_lift.json`.
