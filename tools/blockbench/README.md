# Анимации оружия в Blockbench

[Открываемый проект — pale_animation_workspace.bbmodel](pale_animation_workspace.bbmodel).
Это отдельная редакторская сцена. Авторский меч сохранён: 31 куб, прежние UV и исходные пиксели текстуры. Непрозрачные цветные кубы манекена используют добавленную область **редакторского** атласа; игровые файлы арта не менялись.

## Универсальная сцена оружия — помощник 2.0 (19 ноября 2026)

Обнови локальный `toi_workspace.js` через File → Plugins → Tears of Ink Weapon Workspace → Reload (если путь прежний), затем **закрой и снова открой сцену оружия** с включённым Cameras. В панели появятся `New weapon` и `Save for game`.

`New weapon` → выбери оригинальный Java `.bbmodel` с встроенной текстурой → проверь ID анимаций и координаты хвата X/Y/Z в пикселях исходной модели → сохрани отдельный `.bbmodel` → открой его. Для файлов внутри репозитория помощник пытается подставить grip/offsets из `weapon_anims/<id>.json`; если их нет, укажи сам. Все четыре авторских Display берутся из модели. Исходник не меняется, новый проект имеет пустой список анимаций. `Save for game` сохраняет отдельный .bbmodel со всеми ключами и метаданными для импортёра, не игровой JSON. Обычный Save Project сохраняет метаданные при включённом помощнике. После обновления плагина переоткрой сцену с диска.

Пилот поддерживает Java кубы с face UV, одной используемой встроенной текстурой (одинаковые дубликаты разрешены) и положительным однородным Display scale. Импортёр принимает метаданные v2 и требует совпадения реальной игровой геометрии/UV, grip, Display и offsets. Новое незарегистрированное оружие можно анимировать, но игровой импорт требует регистрации. GUI и живой Minecraft ещё не проверены.

## Автоматическая генерация третьего лица — помощник 2.1.0 (19 ноября 2026)

Обнови `toi_workspace.js` (File → Plugins → Reload), сохрани/переоткрой свою сцену с Cameras и перейди в Animate.

- **Generate F5** — выбери анимацию слева и нажми кнопку. Рассчитываются F5-ключи плеча/руки и кисти из FP-ключей той же анимации, по обеим рукам с FP-ключами. Существующий F5 требует явного подтверждения замены; незадействованная рука и FP не меняются. После генерации открывается F5.
- **Generate all F5** — обрабатывает все анимации, у которых есть FP и ещё нет ни одного F5-ключа. Пропускает ручной F5 и неподдерживаемые клипы, выдаёт отчёт.
- **Sync timing** — добавляет в уже существующие линейные F5 rotation-каналы ключи в моменты FP (в том числе начало/конец), с точным линейным значением. Не перемещает старые ключи и не переписывает позы; сложные кривые/step/split и несовместимые каналы пропускает. Это не автоматическое изменение моментов попадания.
- Все изменения в Animate одним действием Undo (Ctrl+Z), без автоматического сохранения. Меню View дублирует кнопки. При замене выбранной анимации действующие F5-треки только анимированных в FP рук пересчитываются; в пакетном режиме ничего существующего не заменяется.

Математика — порт базовых Claude `base4/solve4` (`tools/preview/third.py`): grip, наиболее дальняя точка геометрии, lead .5, reach 1.3, реальные Display/повороты и иерархия FP. Положение плеча сохраняется, клинок не перемещается отдельно от руки; F5 сохраняет ориентацию клинка FP в редакторских координатах. Углы закладываются в локальные ZYX rotation-ключи с непрерывным выбором Euler-ветви. Запекание по snapping клипа (20–60 Гц) плюс исходные моменты FP. Поддержаны числовые linear, step, Catmull-Rom и Bezier; split-key, выражения, animated scale/global/quaternion и произвольные кости необходимо сначала запечь/исправить. Для step используются дополнительные отсчёты непосредственно перед скачком. Не переносится body yaw, особая постановка F5/ручные corrections и серверные hit timings. Циклическое wrapping игровым импортёром по-прежнему не поддерживается: для импорта использовать once/hold.

Проверяй F5 спереди и сзади; результат — рабочая заготовка, не гарантия отсутствия пересечений с телом. Мод, установленные игровые анимации, авторские модели, FP-ключи и серверный баланс не меняются. GUI Blockbench и живой Minecraft требуют авторской проверки.

## Быстрый старт

1. В Blockbench **5.2.2 или новее** установи **Cameras — JannisX11** через **File → Plugins**. Это плагин редактора, GeckoLib в мод не нужен.
2. Там же нажми **Load Plugin from File** и выбери [toi_workspace.js](toi_workspace.js). Подтверди загрузку нашего помощника. Сохрани исходное имя файла. Плагины нужно загрузить **до открытия проекта**, иначе неизвестные камеры могут потеряться при сохранении.
3. **File → Open Model** → `pale_animation_workspace.bbmodel`. С помощником автоматически открываются два окна: **слева свободный редактор, справа закреплённый кадр 16:9**. Кнопки сверху: **FP 1 / FP 2**, **F5 1 front / F5 2 front / F5 back**. Один риг виден, другой полностью скрыт. Если расположение окон сбилось: **View → Tears of Ink: restore split workspace**.
4. **Animate** → `demo_single_guard` или `demo_dual_guard` → Play. Длительность секунду; ключи в **0 / 0.25 / 0.75 / 1 с**. Это примеры редактирования, а не замена принятого блока.
5. В Outliner раскрой активный риг → `body` → `right/left_shoulder` → `right/left_arm` → `right/left_sword`. Выбери **arm** и вращай мышкой: меч идёт вместе с рукой. Выбери **sword**: собственное вращение вокруг рукояти. На нужном времени Rotate создаёт ключ. **Редактируй кости в Animate**, оставляя исходные pivot и кубы в Edit на месте.
**О костях `shoulder` и `arm`:** это не плечевой и локтевой суставы персонажа. У обеих костей **одинаковый pivot**; `shoulder` — родитель `arm`, а `arm` — родитель `sword`. Их вращение обычно выглядит одинаково, но повороты суммируются. Для обычной постановки достаточно вращать `arm` и отдельно `sword`. Наличие `shoulder` предусмотрено пилотным ригом и импортёром: не удаляй и не переноси эти кости в Edit.

6. Сохраняй свою копию через **File → Save Project / Save Project As** в `.bbmodel`, **не Save Model** в Bedrock geometry. Не перезаписывай игровые модели. В веб-версии разреши обычное скачивание файла; для постоянной работы удобнее настольный Blockbench.

Без нашего помощника файл открывается с непрозрачным F5-манекеном; автоматический split и переключатели требуют помощника. FP и F5 — отдельные tracks в одном клипе: постановка в одном ракурсе **не переписывает** другой. При импорте они соединяются в соответствующие игровые каналы.

Будущие сохранения `.bbmodel` не попадут в игру автоматически: после изменения файла потребуется повторный импорт и обновление отдельной тестовой библиотеки. Редакторская камера пока не откалибрована по игровому кадру; сравнение выполняет автор в Minecraft.

## Камера и границы точности

FP находится в **camera/hand space**, а не на голове мирового Стива. База рассчитана существующей математикой `tools/preview`: независимые правый/левый Display, масштаб 0.68, общий mount, idle offset, настоящий grip и нейтральный swing/equip Бледного. F5 — мировые плечевые pivot, исходный наклон руки и независимые third-person Display. Технические руки соединяют плечо с измеренным хватом; это **схематичные направляющие**, не Minecraft skin/IK.

FP: **70° вертикальный FOV**, крест в центре; пунктир — ориентир верха HUD при условном кадре 960×540 (зависит от GUI scale, это не полный HUD). При другом FOV меняй свойство камеры `TOI_FP_70` и нажми кнопку FP. F5 front/back — обзорные камеры, не симуляция столкновения игровой камеры со стенами.

**Не откалибровано по живому Minecraft.** Изменения FOV, покачивание, ходьба, взгляд, экипировка и реальное освещение не проверены. Правый кадр прямо помечен `Minecraft comparison pending`. Нужна сверка одинаковых моментов 0/25/50/75/100% в игре. Не называем его game-accurate до этой проверки.

## Импорт пилотных клипов

Нужны Python, `numpy`, `Pillow` — те же зависимости, что у `tools/preview`.
Из корня репозитория:

```bash
python tools/blockbench/import_weapon_animation.py \
  tools/blockbench/pale_animation_workspace.bbmodel \
  --clip animation.toi.demo_dual_guard --name bb_test_guard \
  --output work/blockbench/guard.json --dry-run
```

Убери `--dry-run`, чтобы сохранить отдельный JSON. Повторный импорт одинакового проекта детерминирован. Dry-run показывает diff и ничего не пишет. Выход: `animations` с шестью **новыми** именами: FP `bb_test_guard`, `bb_test_guard_off`, плюс их F5 `*_shoulder` / `*_wrist`. Существующие имена и файлы под `src/` защищены от перезаписи. Этот JSON **сам по себе не включает приём в игре**: интеграция новых имён в события — следующий этап после просмотра пилота, с отдельной игровой оценкой автора.

```bash
python tools/blockbench/preview_import.py work/blockbench/guard.json \
  --name bb_test_guard --output work/blockbench/preview
python -m unittest discover -s tools/blockbench -p 'test_*.py'
```

Предпросмотр использует существующую программу Claude **tools/preview**, с библиотекой клипов в памяти; ресурсы игры не переписывает. Готовые примеры: [previews](previews/README.md).

### Что пересчитывается

Импортёр собирает матрицы **всей цепи родителей**, включая исходный поворот sword bone и локальные ключи; Blockbench Euler **ZYX**. Из мирового положения/ориентации меча решает FP translation и XYZ rotation относительно **своего** Display и реальной рукояти. F5 отдельно решает плечевой ZYX и локальную кисть XYZ через ItemInHandLayer и независимый third-person Display. Прямого копирования XYZ руки в меч нет.

Все времена — **секунды клипа**, translation — **пиксели модели (16 = блок)**, rotation — **градусы**. Сохраняются длительность и исходные времена ключей, добавляется сетка `--fps 60` (20–240). Linear, step, Catmull-Rom, Bezier запекаются. Bezier вычисляется точным решением кубической кривой времени; Blockbench показывает её приближением в 200 сегментов, небольшая разница между ними возможна. Для быстрых сложных движений увеличивай FPS и проверяй GIF. У split-keyframe есть дополнительные отсчёты по сторонам разрыва.

Экспорт opt-in: `smooth:false`, quaternion `rotation_mode:slerp`, `third.arm_space`, `third.wrist_xyz`, `third.baked`. Полная кисть XYZ нужна для собственных поворотов sword bone; baked исключает повторные игровые F5 fades поверх уже поставленного движения. Старые клипы без флагов работают прежним путём. Возврат в спокойную стойку ставь ключами **внутри длительности**: импортёр не придумывает choreography, hold или return, не меняет серверные окна попаданий/tempo/урон. Последний ключ может быть удержанной позой, но игровое время её удержания отдельно задаёт механика.

### Поддерживаемая область и диагностика

Пилот привязан к этому ригу Бледного, а не к произвольному Blockbench-проекту. Manifest [pale_workspace_rig.json](pale_workspace_rig.json) — резерв, если редактор без помощника удалил custom metadata. Изменённые Display/mount/grip или авторские исходники требуют новой калибровки. Кубы заблокированы; pivot, иерархию, scale и геометрию в Edit не перестраивай.

- FP: локальные вращения плеча, руки и меча; перемещение руки/меча вычисляется через родителей.
- F5: вращения плеча/руки и меча. **Перемещение F5-плеча или рукояти относительно руки отклоняется**, потому что текущий Minecraft renderer привязан к плечу и кисти. Вместо незаметно неправильного результата будет понятная ошибка.
- Scale, Molang, global/quaternion keyframes, камера/effects tracks, анимация тела/головы и циклическое wrapping не переносятся; сначала запеки поддерживаемые локальные ключи. Нужна положительная длина и snapping; обязательны кости и камеры.
- Поворот головы/автоматическая поддерживающая рука при одиночном двуручнике остаются поведением игрового рендера, не дополнительными tracks этого пилота.

### 2.1.1 — восстановление калибровки открытой сцены
Reload больше не теряет метаданные активного проекта: они сохраняются на объекте проекта и в корне .bbmodel. При отсутствии данных сначала читается метадата локальной сохранённой копии (если доступна и совпадает геометрия/риг), затем для точной геометрии и pivot исходного Бледного двуручника автоматически восстанавливается встроенная V1-калибровка. Имена проекта, UUID анимаций и количество клипов не влияют. Ключи, модели и файл на диске не переписываются. Для несовпадающей сцены калибровка не угадывается. После Reload можно нажать Generate F5 в текущей сцене; затем сохранить обычным способом. Если сообщение осталось, передать копию текущего .bbmodel для диагностики, не создавать заново сцену.


## 2.2.0 — обратный импорт игры и перенос клипов (19.11.2026)
**Import from game** во вкладке Animate: выбери основной JSON из `weapon_anims` для открытого оружия (с grip), при наличии его дополнительный `*_bb_author.json` и необязательно JSON из `weapon_combos`. Можно выбрать одновременно. Диалог списка: один клип на строку, `right + left`, либо `+ left` для одного левого. С combo по умолчанию выбираются текущие steps/dual_steps, для Бледного без combo — известные активные парные атаки. Без combo на других предметах список эвристический, уточняется вручную. Все клипы добавляются с `game_`, совпадения получают `_copy2`, ничего не затирается. 20–60 отсчётов/с, исходные времена, независимые FP/F5 руки, игровые smooth/ease/slerp, third.source (включая масштаб времени авторских фаз), wrist_source, mirror, no_cross, turn, arm_space, wrist hold и вход/выход F5. Отдельный клип в базовом времени, без серверного tempo, длинных hold/return после length, стыка с предыдущим движением, body yaw/head look/поддерживающей руки; не точный захват игрового кадра. Сдвиг рукояти push, absolute, анимированный scale, щиты без grip не импортируются. Базовый JSON должен соответствовать grip и offsets рига, Display берётся из открытой сцены.
**Copy clip → перейти на вкладку другого TOI-проекта → Paste clip** — локальный буфер до перезагрузки плагина, FP/F5 кости сопоставляются по имени, новые UUID, все ключи остаются редактируемыми. Новое имя при совпадении; перенос между оружиями копирует локальные движения, не гарантирует одинаковую экранную траекторию и требует поправки хватов. Undo одним действием. Обычный Ctrl+C/V работает в списке анимаций Blockbench, но для разных UUID предпочтительны кнопки.
Готовая отдельная сцена [исторический pale_current_game_combos.bbmodel](https://github.com/TarKrakov/tearsofink/blob/ccfd89e7ff8291b7e678d54e64fd61e71a64c601/blockbench/pale_current_game_combos.bbmodel) содержит текущие 3 одиночных и 5 парных ЛКМ-клипов, рассчитанные из основных ресурсов и актуальной combo-конфигурации; исходная авторская сцена не изменена. Используй **New weapon** с `src/main/resources/assets/tears-of-ink/models/item/holy_pistol.bbmodel`, а не с исходным `blockbench/holy_pistol.bbmodel`: экспортная копия сохраняет все 14 кубов, UV, текстуру и авторские правые Display, содержит зеркальные левые Display и запечённые прямоугольные повороты. Модель и её хват нужно визуально сверить в Minecraft. `node tools/blockbench/export_holy_pistol.js --check` — структурная проверка.

Клипы для автора: `aim_enter`, `aim_exit`, `shoot`, `shoot_aimed`, `reload`, `wild_shot`, `dual_aim_enter`, `dual_aim_exit`, `dual_shoot`, `dual_shoot_aimed`, `dual_reload`. Не изменять pivot в Edit. Ориентиры: 0.25 с прицел/выстрел, 1.9 с reload, 3.0 с dual_reload; длительность перезарядки синхронизируется с фактическим серверным прогрессом, отдача может перекрывать его начало. `wild_shot` — около 0.6 с, выстрел уже в момент серверного события. Сохрани `holy_pistol_animation.bbmodel` через Save for game и передай авторский файл. Технический импорт: `node tools/blockbench/import_holy_pistol.js <file>` (dry-run), затем `--write`; он создаёт отдельную библиотеку `holy_pistol_bb_author.json`.
